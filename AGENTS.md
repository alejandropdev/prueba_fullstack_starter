# AGENTS.md

NestJS 10 + TypeORM + PostgreSQL starter for a coding challenge. Repo language is **Spanish**: keep comments, DTOs and user-facing error messages in Spanish (e.g. `'Credenciales inválidas'`, `'Factura no encontrada'`).

The actual deliverable being evaluated is the **missing** business feature: safely *anular/corregir facturas* (void/correct invoices). Auth, DB schema and read-only endpoints are scaffolding to reuse, not to rebuild.

## Restricciones (restricciones de negocio infranqueables)
- **Aislamiento multi-tenant**: ningún tenant puede ver ni afectar los datos de otro tenant. Todo query de escritura/lectura debe filtrar por `tenantId`; acceder/afectar un registro ajeno responde `404`.
- **Precisión del dinero**: los montos se manejan con la precisión exacta de la fuente (`NUMERIC` → `string`); no puede descuadrarse ni un peso. Prohibido operar dinero como `number`/`float`; usa los helpers `decimal.js` de `src/common/utils/money.util.ts`.
- **Consistencia de saldos**: cualquier cambio al saldo de una factura (anular, corregir, pagar) debe dejar el registro en estado consistente: `saldo_pendiente <= monto_total`, montos `>= 0`, y únicamente estados `emitida | pagada | anulada`.

## Run
- Start DB then app: `docker compose up -d` → `npm run start:dev` (API :3000, Swagger `/docs`).
- `.env` is commit-ready and intentionally complete (dev creds). Don't create/copy it. Only edit `APP_PORT`/`DB_PORT` on port conflicts.
- `docker/postgres/init/*.sql` runs **only** on first volume creation. Reseed by wiping the volume: `npm run db:reset` (= `docker compose down -v && docker compose up -d`). Edits to init SQL won't apply otherwise.

## Database & migrations (critical)
- `synchronize: false` by design — schema is versioned, never auto-DDL.
- Migrations are generated by **diffing the live DB** (Postgres must be up):
  - `npm run migration:generate -- src/database/migrations/NombreMigracion`
  - `npm run migration:run` / `npm run migration:revert`
- New entities MUST be added to the `entities: [...]` array in `src/database/data-source.ts` (shared by the CLI and `app.module.ts`). If omitted, `migration:generate` emits `DROP TABLE` for tables it can't see.
- Base tables were created by raw SQL, not migrations; add new tables/columns via new migrations.

## Conventions (verified in code)
- DB columns `snake_case` via `@Column({ name: '...' })`, TS properties `camelCase`.
- Money is Postgres `NUMERIC` → **string** in TS. Do math via `decimal.js` helpers in `src/common/utils/money.util.ts` (`toMoney`, `addMoney`, `subtractMoney`, `isGreaterThan`). Never cast money to `number`/float.
- Multi-tenant: every business query must filter by `tenantId` (pattern in `facturas.service.ts:15` / `:23`). Cross-tenant record → **404, not 403**.
- Protect new controllers with `@UseGuards(JwtAuthGuard)`; read the user via `@CurrentUser()` which yields `{ userId, tenantId, email }`. Reuse `auth`/`common` code as-is.
- Factura estados: `emitida | pagada | anulada`. Schema enforces `saldo_pendiente <= monto_total` and `monto_total >= 0` — preserve these invariants (e.g. when voiding/correcting).
